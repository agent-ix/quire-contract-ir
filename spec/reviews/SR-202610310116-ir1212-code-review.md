| FND-001 | high | A selected object with declared operations yields a successful type view that omits those operations, so it cannot construct the expected QSL TypeEnvironment. | crates/quire-contract-model/src/checked_package/v2/runtime_type_projection.rs:55 |

## Evidence

The public `SelectedTypeObject` contains identity, supertypes, declared fields and effective fields but no operation declarations. The projection's ObjectType branch builds and returns that type without checking whether `model.object_types[declaration.node].operations` is nonempty (runtime_type_projection.rs:458-564). QSL's `TypeEnvironment` takes `ObjectTypeDeclaration` values whose `operations` are part of the declaration (qsl-semantics/src/value/declaration.rs:434-510). Thus an admitted model with an object operation can return `Ok(SelectedTypeDeclarations)` although this view cannot supply that operation to the expected environment. The new positive test uses objects with fields only. Either carry the admitted operation declaration facts needed by that environment or refuse this case as an incomplete view.
