## Evidence

FND-001: CheckedPackageV2::eq compares wire and kinds only (v2/mod.rs:785-791); selected domain documents are supplied in CheckedPackageEvidence and retained in models outside the wire. Two admissions of the same wire with different document bytes can compare equal. The read guard permits equality after pointer inequality and then returns this index's row.

FND-002: RetainedModels::operation_classes uses effective_operation_names, whose resolver walks ancestor declarations (model_members.rs:1424-1450). The new join loops only owner.object_type().operations, so an admitted anchor for an inherited operation cannot match its original member identity. The test has one directly declared ObjectType operation.

FND-003: FR-352-AC-10 and FR-354-AC-3 require a source-declared anchor without a selected model member to return typed unavailable-witness. The new branch and test use UnavailableModelMember, although UnavailableWitness exists as the named outcome.

FND-004: The PR adds SelectedOperationMemberError, SelectedOperationMemberErrorCode, SelectedOperationMemberRow, and SelectedOperationMembers to the model crate root. The FR-019 Public items table's V2 Exact type projection row does not list them; TC-058 compares the exact exported set.

| FND-005 | medium | The new selected operation identity's name is never checked against the admitted anchor/member, so a mismatched checked operation name is accepted. | crates/quire-contract-model/src/checked_package/v2/operation_witness.rs:195 |

The new `SelectedOperationIdentity` has a public `operation` field. The row join checks `original_operation_identity` and `body.operation`, then accepts the row without comparing `selected_operation_identity.operation`. Changing only that field from `scaled` to `reset` in the public test's row would still return success and expose the wrong selected operation identity. The `declaring: EffectiveId` remains a producer fact; the operation name is directly checkable from admission.
