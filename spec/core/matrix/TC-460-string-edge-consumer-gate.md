# TC-460: Reject post-intake wire dispatch through the shared scanner

## Description

Exercise Contract IR's normal scan prerequisite with the real authoritative
external executable. Keep command/gate failure, neutral-marker compiler behavior,
open identity controls and the actual repository result distinct. No controlled
fixture substitutes for a clean scan of both real production roots.

## Test Procedure

1. Install the authoritative scanner through QSL FR-064's Git route, or select
   that installed executable by explicit path. Inspect the normal Make graph for
   the scan prerequisite under `lint`, retained under `ci`, and the exact base,
   two source roots and checked-in rules arguments. Run that prerequisite in a
   controlled consumer tree containing both nonoverlapping roots.
2. Begin with an enum-based post-intake decision. Insert a real unmarked string
   `match` over a node-tag spelling into its production source. Run the same
   prerequisite and require the actual violation naming that file and item.
   Restore the typed decision and require a completed clean scan.
3. Compile and run a genuine intake converter marked by the neutral owner's
   actual proc macro. Put an unmarked adverse decision beside it and confirm
   only the latter is reported. Repeat the adverse decision with a look-alike
   qualified macro and with a comment-only mark; neither is an exemption.
4. Preserve a comparison between two caller-supplied keys and confirm it is not
   reported. Separately exercise a detector-visible open-text comparison whose
   result only reaches a non-branching display sink: require its valid rule for
   a clean scan, then remove it. Attempt a rule for the branch-gating wire
   decision and require a rule error. Record that variable-to-variable and
   indirect dataflow recognition are outside the syntactic detector's coverage.
5. Exercise missing executable, malformed rules, missing root and Rust parse
   failure through the same prerequisite. Verify failure reaches Make, with no
   fallback, skip, ignored status or misleading clean result.
6. Inspect Cargo metadata and compile the real marked functions against the
   neutral crate. Retain FR-028's no-QSL-in-any-kind and acyclic-model controls.
   Review every new marker and rule against the actual function's conversion
   boundary; do not exempt whole files or validators.
7. Run the actual normal repository invocation over `src` and
   `crates/quire-contract-model/src`. Keep unresolved reports failing and route
   them to their source owners. Only an actual completed clean result backs
   FR-056-AC-8. Preserve existing intake/refusal/conformance tests during each
   owning semantic migration.

## Expected Results

The adverse wire-string mutation fails with exit-one diagnostics; the restored
control passes. The actual marker compiles without changing the converter's
behavior, and look-alikes do not hide violations. Open-key controls remain
accepted within the documented detector limits. Branch suppression and invalid
requests fail, and every such failure propagates through the normal prerequisite.
The dependency graph contains no QSL edge. The real repository scan passes only
after all reported occurrences are resolved by valid edge marking or their
owning source migrations; neither fixture success nor this procedure alone
establishes global AD-004 Q-6 completion.
