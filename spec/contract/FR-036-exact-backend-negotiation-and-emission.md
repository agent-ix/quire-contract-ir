# FR-036: Negotiate exact backend capability before artifact emission

## Description

When a backend provider receives a ContractPackage request, the provider shall
negotiate exact per-item capability, domains, bounds, options, and tool lock
before it emits an artifact or result.

## Inputs

A ContractPackage, requested claims, model domains, provider manifest, limits,
explicit bounds, and immutable Rust/tool/dependency/options lock.

## Outputs

One per-item `supported`, `requires_bound`, `unsupported`, or
`invalid_request` disposition; only a fully negotiated request may emit typed
artifacts, results, and complete accounting.

## Behavior

The provider shall derive finite Kani and property-test domains from model
domains or explicit proof requests, including inclusive endpoints and checked
conversions. The provider shall keep preconditions, postconditions, invariants,
and frame clauses distinct. A graph, temporal, or protocol item shall emit only
when a recorded finite encoding has one-to-one semantic correspondence. When
that correspondence is absent, the provider shall return `requires_bound` or
`unsupported`. The provider shall generate Rust-only artifacts with `publish =
false`. The provider shall identify package, claim, domain, bounds, options,
toolchain, and dependencies.

## Acceptance Criteria

| ID | Criteria | Verification |
| --- | --- | --- |
| FR-036-AC-1 | Generated symbolic ranges equal model-derived inclusive domains, including boundary values. | Test (TC-045) |
| FR-036-AC-2 | Missing bounds, absent exact encodings, and unsupported meaning produce a per-item non-success and no artifact. | Test (TC-045) |
| FR-036-AC-3 | Every generated item records separate precondition, postcondition, invariant, frame, provider, and tool/options provenance. | Test (TC-045) |
| FR-036-AC-4 | A provider completes accounting for every requested item before exposing generated bytes or a result. | Test (TC-045) |
