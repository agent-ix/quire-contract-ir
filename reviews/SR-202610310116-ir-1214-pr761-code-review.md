# IR-1214 checked-term sidecar code and Rust review

## Summary

Ticket: IR-1214. Reviewed PR #761 at `b757af11` against FR-354-AC-4 and QSpec FR-322-AC-288, AC-290 and AC-292. The diff introduces a closed three-array sidecar, reader intake, bounded dispatch read, and public exports. No applicable AssuranceProfile was found under this repository's spec tree.

## Verdict

**FAIL.** The dispatch validator can admit a candidate key unrelated to the selected call and can treat an arbitrary admitted node as an operation body. The public read also conflates a foreign request with an absent table.

## Findings

| ID | Severity | Summary | Refs |
| --- | --- | --- | --- |
| FND-001 | high | A root candidate key passes when its `{package,node}` names any selected object type, without joining that effective declaration to the call's selected operation or the candidate. An unrelated selected object can therefore be admitted as a dispatch candidate. | `crates/quire-contract-model/src/checked_package/v2/dispatch_projection.rs:144` |
| FND-002 | high | `operation_body` and `effective_precondition` are checked only for a local graph entry. A call node, type node, or unrelated function can be accepted as the candidate's executable body or precondition; the new positive test explicitly uses the call node as `operation_body`. | `crates/quire-contract-model/src/checked_package/v2/dispatch_projection.rs:155`; `tests/it/checked_package_v2_model_members.rs:350` |
| FND-003 | medium | `dispatch_candidates` returns `Missing` for a foreign or unknown requested application, although FR-354 requires a typed foreign or absent join outcome. | `crates/quire-contract-model/src/checked_package/v2/dispatch_projection.rs:215` |

## Coverage

- FR-354-AC-4, role: examined. Excerpt: "The dispatch projection preserves every admitted candidate in producer order with its effective precondition term reference; a missing or ambiguous candidate/precondition join refuses without choosing a candidate or evaluating a predicate."
- QSpec FR-322-AC-288, role: examined. Excerpt: "A dispatch record preserves the selected operation witness, receiver context and candidates in producer order, with each candidate's selection key, operation-body handle and nullable effective-precondition body handle."
- QSpec FR-322-AC-290, role: examined. Excerpt: "Each candidate selection key ... matches the candidate's admitted effective declaration identity" and each body/precondition handle joins to the admitted package.
- QSpec FR-322-AC-292, role: context_only. Excerpt: "Read work charges every sidecar row ... and candidate entry before inspection" with exact boundary and first failing locus.
- FR-019 public inventory, role: examined. Inspected the new root exports and their listed checked-term reader types.
- Rust review inspected closed serde shapes, required nullable fields, iterative `CheckedEffectiveId` encoding, work charges, malformed input paths, borrowed view lifetime, and the focused TC-233 tests. No changed CI workflow or unsafe code appears in the diff. The lead owns the aggregate gate on the final reviewed head.
