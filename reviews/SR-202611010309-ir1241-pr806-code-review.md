## Summary

Reviewed the frozen Makefile-only change against IR-1241, the removed SHA declaration-key test, current QSpec fixture tests, and the requirement that the conformance target fail if its published positive fixtures disappear. No Rust, production reader, or workflow file changed.

## Verdict

**CONDITIONAL** — the obsolete digest-key guard must be replaced with a one-run guard for the existing production-reader positive-fixture test.

## Findings

| ID | Severity | Summary | Refs |
| --- | --- | --- | --- |
| FND-001 | medium | Removing the exact-name guard without retargeting it lets `make conformance-qspec` succeed if the current positive-fixture test is later removed or renamed while other conformance tests still run. FR-038-AC-107/176 require the target to execute the published positive fixtures and fail if one is absent. Retarget the one-run guard to the existing `tc_048_qspec_all_positive_packages_and_owner_identities` test; keep the obsolete SHA declaration-key test removed. | Makefile:98; tests/conformance_qspec/main.rs:1417 |

## Coverage

- FR-038-AC-107 (examined): The conformance target reads every QSpec positive V2 fixture directly from `QUIRE_SPECIFICATION_DIR`, requires production-reader admission with published structural IDs and complete bodies, and fails if a fixture is absent.
- FR-038-AC-176 (examined): The conformance target reads every positive package with its selected domain document, checks exact structural node IDs, owners, graph order and complete bodies, and fails on missing, malformed, unadmitted or unequal source.
- Current positive-fixture test (examined): `tc_048_qspec_all_positive_packages_and_owner_identities` iterates `POSITIVE_ALL`, reads each package through the production reader, and compares retained structural IDs, owners and bodies with published wire.
- Retained TC-229 guard (examined): `make conformance-qspec` still requires two owner tests to run exactly once; it does not guard the positive-fixture test above.
- Removed digest test (context only): `tc_048_qspec_model_declaration_keys_use_production_derivation` asserted SHA-256 declaration-key preimages and was deleted by IR-1141 structural NodeId commit `0fa7cfdc`; the digest-key obligation is obsolete.
- Scoped command evidence (context only): The coder's current `make conformance-qspec` run reports five `ir1083_` tests, 165 QSpec conformance tests and two TC-229 tests passing against QSpec `a90a4903`.

## Dispositions
