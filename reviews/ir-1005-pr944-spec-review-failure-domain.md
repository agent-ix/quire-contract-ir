## Summary

Ticket: IR-1005. Reviewer-only spec-review/failure-domain pass over `git diff origin/main...HEAD` of quire-contract-ir PR #944 at 40ac6f940936280b84a5c88a2cef846f3c59aef2, against owner APIs at origin/main of quire-spec-language, quire-observation, quire-integration and quire-contract-model, and quire-mltl origin/main plus open PRs #17/#18. Sibling quire-integration #88 (IT-022) was read for contradictions only.

## Verdict

**FAIL** — one high and four lower findings in edge handling. The native outcome column covers all twelve `ReportOutcome` variants, missing valuations are never false, and corrections compare complete predecessor bytes on both sides. The gaps are in totality of the side and row tables, unaddressed native request members, cross-type equality, and within-row cause precedence.

| FND-001 | high | The R1-R8 totality claim does not follow from the text. (a) R6 excludes pairs where 'R7 nor R8's state condition holds', but 'state condition' is not defined. If it means R7's state part (both final, equal Booleans) without `P`, then an equal-final pair with `P` false (the central premise-mismatch case) satisfies none of R6, R7 or R8, so it gets no decision. (b) The side table claims every side gets exactly one state, but a TL result with execution `Failed` fits no column: it is not refused, unavailable, unsupported, incomplete, contradicted or final, and 'pending' is limited to completed results. A native strict read refused with `InvalidPredecessor` is excluded from `refused` and has no outcome either. Failure: implementers resolve these differently, giving different decisions and cause lists for one pair. Fix: define R6 as 'both in {final, pending} and neither R7 nor R8 holds', and add explicit states for TL `Failed` and native `InvalidPredecessor`, or state that rows read them directly. | spec/temporal/functional/FR-350-native-temporal-tl-correspondence.md:373-412 |
| FND-002 | medium | Several `EvidenceRequest` members are neither checked nor recorded: `correspondence` (an EvidenceRef the native report echoes byte for byte; native corrections refuse `correspondence-changed`, qsl-eval evidence/call.rs:499-501), `cover`, `progress_ledger`, `trigger_scope`, `native_valuations` and `limits`, plus the non-identity members of each `positions[i].observation` EvidenceRef. Failure: two native reports computed under different correspondence references or position authorities join under one record. AC-3's 'each member's source input' cannot be exact for these inputs. FR-350 also does not say whether the native `correspondence` must name this bridge's record, which is an acyclicity question the spec leaves to the coder. Fix: state for each member whether it is required, compared or recorded, and state what `request.correspondence` must hold (for example the bridge-definition identity, which is stable across corrections). | spec/temporal/functional/FR-350-native-temporal-tl-correspondence.md:79, 326-353 |
| FND-003 | medium | Step 6 requires native `decision_closure`/`surrounding_closure` (`ProgressClosure` Open/Closed) to 'equal' QObs closure views (scope, clock, required sources, boundary and state), and requires u64 progress to equal QObs progress watermarks (canonical text). That equality is not defined across these types. For fixed-sample clocks, the IR `ClockConfiguration::FixedSample{epoch, period, unit}` must 'equal' the QObs range `{epoch_nanos, period_nanos}`.
