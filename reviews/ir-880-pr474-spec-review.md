## Summary

Ticket: IR-880. PR agent-ix/quire-contract-ir#474,, diff against origin/main (the merge base). This review checks the amended TC-456 procedure against the planner's intent: registered STD-001 code names such as `Std001Code::KANI_SOLVER_ABSENT` are exempt from the forbidden-vocabulary rule, the exemption is exactly the set STD-001 registers and is derived from the registry (no glob, prefix, regex or hand-copied list), any forbidden term outside that set still fails (including a new unregistered const next to `Std001Code`), and two mutations are required: an unregistered `solver` const is caught, and removing a registry row removes its exemption.

Facts re-measured on the tree: STD-001 (`spec/core/functional/STD-001-diagnostic-registry.md`) lists every registered code in the first column of its `Code` tables, so the set can be derived from the registry text. `tests/it/nfr003_invalid_input.rs::std001_declared_codes` already parses four of these tables this way. The `Std001Code` constants are generated by `registered_codes!` in `crates/quire-contract-model/src/code.rs` (`KANI_SOLVER_ABSENT => "kani_solver_absent"`), and every constant name is its code in uppercase. `kani_solver_absent` is the only registered code that holds a term from `FORBIDDEN_PUBLIC_NAME_TERMS` (`solver`). No public schema contains `solver`. `Std001Code::REGISTERED` is a public associated const whose array value holds `"kani_solver_absent"`.

## Findings

| ID | Severity | Summary | Refs |

| FND-001 | medium | TC-456 now admits `Std001Code::KANI_SOLVER_ABSENT`, a public model name that NFR-002-AC-1 as written forbids. Neither NFR-002 nor any decision states the exemption, so once the test lands the matrix would mark AC-1 verified while the literal criterion is still violated. The scope sentence in TC-456 ("STD-001 governs registered diagnostic code vocabulary, while TC-456 governs model vocabulary") is a rationale the requirement does not carry. Needs a planner decision on where the exemption is anchored without weakening AC-1. | spec/core/matrix/TC-456-public-name-portability.md:33-44 |
| FND-002 | medium | The exemption and the removed-row mutation name constant "string values", but the procedure never requires the Rust enumerator to read a constant's value. It only enumerates names. The outcome for `Std001Code::REGISTERED` is also unspecified: it is a `Std001Code` associated const whose array value holds `"kani_solver_absent"`, and it is not one of the exempt constants. If values are enumerated, the test fails on the real tree. If they are not, the "reject that name and value" half of the mutation cannot be checked. | spec/core/matrix/TC-456-public-name-portability.md:26-29, 36-43, 56-58 |
| FND-003 | medium | The removed-row mutation acts on a "registry fixture" that the procedure never defines. Nothing requires that fixture to pass through the same STD-001 `Code`-row extractor as the main path. A test could hand-build a code set without `kani_solver_absent` and pass the mutation while the real derivation from STD-001 goes unexercised. ## Verdict

CHANGES REQUESTED, three medium findings. The amendment otherwise meets the planner's intent. The exemption is derived from STD-001's `Code` rows. It is not inferred from `Std001Code::REGISTERED` or source. It forbids prefix, glob, regex and separately kept lists. It is limited to `Std001Code` constants, by name and value, and does not cover same-spelled items or schema names. A row with no constant exempts nothing. Forbidden terms outside the set still fail. Both required mutations are present: an unregistered `solver` const, and a removed `kani_solver_absent` row. The derivation is feasible on the tree, because every constant name is its STD-001 code in uppercase. The NFR-002-AC-1 text is unchanged. FND-002 and FND-003 can be fixed in the TC-456 text. FND-001 needs a planner decision: either record the exemption at the requirement or decision level without weakening AC-1, or accept it with a stated reason. The pre-existing tension with NFR-002-AC-3 (`kani_solver_absent` is a registered diagnostic code, and AC-3 forbids `solver` in diagnostic codes) is outside this diff and is noted as context only.
