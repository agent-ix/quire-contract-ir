# SR-819: evidence review of PR 258 canonical encoding

## Summary

Ticket: IR-533. AC-73 to AC-77 are Test (TC-048), which fits: they are byte comparisons
and bounded-stack runs that a Rust test performs directly. AC-78 is Inspection (TC-048).
The repository has precedent for inspection ACs: FR-013-AC-2 is Inspection (TC-016),
FR-019-AC-1 is Inspection (TC-018), and TC-051 is an Inspection test case. Inspection fits
AC-78's manifest, `deny.toml` and source-shape clauses. Its "derives `FixedShape`" and
"does not implement `FixedShape`" clauses are also compile-checkable. The new ACs are
marked planned with no test, which is honest and is what `quire coverage` shows (FR-038
45/76).

## Verdict

The evidence methods are appropriate. FND-001 is a matrix-hygiene nit.

## Dispositions

Round 1 at 2f491e0a30bd3b29b9ae6f9abf81f28ba09bac81. The author did not add an Inspection
test case. AC-80 is now "Test (TC-048)", backed by a test that reads the manifests,
`deny.toml` and the crate source. It lists every `FixedShape` derive and every `Encode` and
`FixedShape` impl, searches for `const DEPTH`, and runs `make deny`. I accept this. It is an
automated check that fails when a clause is violated, so the method in the AC table now
matches the Property test case that carries it. Adding a separate Inspection test case
would have put two more unbacked rows into the strict count.

Its limit, stated plainly: a source scan proves less than the compiler does. It can miss an
impl generated by a macro, and a static assertion that each named type is `FixedShape`
would be stronger for the derive clause. That is a suggestion for the code PR, not a
defect in this spec.
